# 动态人格（增强）

<img src="logo.png" width="150" align="right" alt="动态人格（增强）" />

让 AI 根据聊天内容自动切换人格，每个人格都有独立的聊天记录。

平时正经干活，被人骂了自动切毒舌人格对线，吵完自动切回来——不用手动换，两边的聊天也不会混。

## 效果长什么样

**装插件之前**

```
你：傻逼机器人
Bot：（还是那副正经脸）请不要这样说话，有什么可以帮你的吗

你：帮我看看这个报错
Bot：（还是那副正经脸）……
```

**装插件之后**

```
你：傻逼机器人
Bot：（自动切到毒舌人格）就这点词汇量也敢来开喷？回去练练再来

你：帮我看看这个报错
Bot：（自动切回正经人格）这个报错是 XXX，改这几行就行
```

再切回毒舌人格，它还记得刚才那场架；切回正经人格，正经这边完全不记得你骂过人。

## 三步装好

### 第 1 步：安装

WebUI → 插件管理 → 安装插件 → 填仓库地址：

```
https://github.com/CGTouhou/astrbot_plugin_persona_router
```

或者手动把整个目录放进 `AstrBot/data/plugins/`，重启。

无需 `pip install`，无额外依赖。

### 第 2 步：建人格规则

WebUI → 插件管理 → **动态人格（增强）** → 配置 → **人格规则** → 添加条目。

一条规则 = 一个人格 + 什么时候用它。最少填三个：

| 字段 | 填什么 | 举例 |
|---|---|---|
| 用哪个人格 | 从 AstrBot 人格列表选 | `贴吧大肥鱼` |
| 这个人格是什么样 | 一句话简介，给判断模型看 | `对骂专用，嘴臭不认输` |
| 什么时候切到它 | **最重要**，什么消息该切、什么不该切 | 见下面 |

```text
只在「攻击对象明确是机器人本人」时命中：
- 直接骂机器人：傻逼 / 垃圾 / 破机器人
- 骂家人且明显连着机器人
- 嘲讽机器人能力、挑衅、复读刷屏

以下不算：
- 正常提问、求帮助
- 骂别的人或事（游戏、系统、群友）
- 单纯带脏字的语气词
- 玩梗、自嘲、开玩笑
```

这段话写得越具体，判断越准。**宁可少切，不要切错**。

### 第 3 步：设默认人格

配置里的 **默认人格** 选一个（比如 `优化后`）。没命中任何规则时用它。

### 验收

找个号发 `/dp status`，能看到配置摘要和每条规则的触发词，就通了。

## 配置怎么填

### 最常改的几个

| 配置项 | 说明 | 建议 |
|---|---|---|
| 默认人格 | 没命中规则时用它 | 选你平时最常用的那个 |
| 让 AI 判断该用哪个人格 | 关掉就只靠关键词 | 关键词够用就关，省延迟 |
| 每个人格独立记忆 | 人格之间聊天记录隔离 | **保持开启** |
| 生效范围 | 哪些会话走这个插件 | 全局用就选「全部会话」 |

### AI 判断相关

| 配置项 | 说明 |
|---|---|
| 判断用的模型 | 选轻量的快的。留空 = 用当前会话模型（**不是**关闭判断） |
| 判断结果复用条数 | 连续 N 条复用上一次判断。**默认 3，推荐 2–4**；越大越省调用、越迟钝，`1` = 每条都判断 |
| 判断时参考几条最近消息 | 用来区分「骂机器人」还是「骂别人」。**推荐 3–5**，`0` 只看当前这条 |
| 判断超时（秒） | 超时直接用默认人格，不会卡住回复。**推荐 5–10** |
| 自定义判断偏好 | 补充说明，比如「这个人格只在群里用，私聊不要切」 |

### 规则里的高级字段

| 字段 | 干什么 |
|---|---|
| 关键词触发 | 命中就立刻切，不调模型。支持正则 |
| 触发后持续几秒 | `0` 只影响当前这条；**推荐 60–300**（1–5 分钟），到期自动切回 |
| 隔离方式 | `inherit` 跟随全局 / `on` 独占对话 / `off` 共用对话 |
| 叠加方式 | `inherit` 跟随全局 / `replace`（默认，只留选中人格）/ `prepend`（两张卡叠加） |
| 关键词重复触发时重新计时 | 关：同一个人格再次命中不续期。开：每命中一次重新计时 |

### 生效范围怎么填

想让某个群不走插件：

1. **生效范围** 选 `只对列表里的会话生效`（白名单）
2. **生效范围列表** 填那个群的群号
3. 群号不知道？在那个群发 `/dp sessionid`

反着想排除某个群，选 `列表里的会话不生效`（黑名单）。

## 命令

需要 AstrBot 管理员权限。

| 命令 | 作用 |
|---|---|
| `/dp status` | 配置摘要 + 每条规则的触发词 + 当前激活状态 |
| `/dp now` | 这个会话现在用的是谁（关键词激活时显示剩余秒数） |
| `/dp clear` | 清空本会话的关键词激活状态和判断上下文（时间线） |
| `/dp refresh` | 清空判断缓存，强制下一条重新判断 |
| `/dp enable` / `/dp disable` | 临时开关（不改配置文件） |
| `/dp restore` | 把不归本插件管的会话还原（指针拨回主对话、解绑人格） |
| `/dp sessionid` | 查看当前会话 ID |
| `/dp migrate [人格名]` | 把当前对话绑定改成指定人格 |

## 两种模式

配置项 **每个人格独立记忆** 决定。

### 开启（推荐）

```
你 ↔ 正经人格  →  对话 A（只有正经的聊天）
你 ↔ 毒舌人格  →  对话 B（只有对骂的聊天）
```

- 聊天记录互不串
- 人格由 AstrBot 原生注入，Skills、工具说明完整保留
- 切人格 = 换对话，模型看到的历史也跟着换

### 关闭

```
你 ↔ 共用对话  →  所有人格共用一条历史
                    └─ 系统提示词 = 默认人格 + 选中人格
```

- 好处：人格卡可以互相补充，比如「默认人格 + 一句『现在你在生气』」
- 代价：所有人格共享历史，切换后能看到别的角色的聊天
- 叠加方式默认 `replace`：只保留选中人格，行为最接近这张卡本身；代价是 AstrBot 原生拼进来的 Skills 说明、工具约定也一并被丢掉
- 想两张卡共存就选 `prepend`：系统提示词里会同时存在默认人格和选中人格，模型会同时受两边影响，Skills 和工具约定也会保留

## 清空历史：`/reset` 和 `/new` 怎么选

两个都是 AstrBot 内置命令，都要管理员权限，但做的事完全不同。

| | `/reset` | `/new` |
|---|---|---|
| 对话本身 | **保留**，只清历史 | **另建一条**，旧的留着 |
| 插件还认它吗 | 认，无缝接着用 | 隔离模式认；非隔离模式会被收编成新的共享对话 |
| 会不会留下用不到的对话 | 不会 | 会，旧的变成只读存档 |
| 适合 | 日常「从头开始」 | 想留档、另开一段 |

### `/reset`

清空历史，对话对象不变，插件继续往这条对话里写。

隔离模式下默认会把**这个会话下所有人格的聊天记录一起清掉**，由配置项 **重置所有人格**（`reset_all_personas`，默认开）控制。只想清当前人格就把它关掉。

### `/new`

新建一条对话，**旧的不删**，留在 WebUI 的对话管理里。区别在这里：

- **隔离模式**：新对话继承当前人格（AstrBot 会把当前对话的 `persona_id` 复制过去）。于是同一个人格有了两条对话，插件每次都取**最近更新的那条**。旧的那条从此不会再被用到，只能在 WebUI 里查看、导出或删除。
- **非隔离模式**：新建的对话没有 `[共享]` 铭牌，插件会在下一条消息把这条空对话收编成新的共享对话（v2.5.5 起），效果等于「重开一段」，原来那条共享对话留档。

### 能切回旧对话吗

**不能。** AstrBot 没有「切换对话」的命令；WebUI 的对话管理只能查看、改名、删除，没有「设为当前对话」的入口。

所以 `/new` 之后的旧对话就是只读存档。如果发现自己经常需要来回切，说明场景更适合 `/reset`。

### 所以

**平时用 `/reset` 就够了。** 它不产生新对话，插件不会留下认不出来的孤儿。

`/new` 留给「这段聊得不错，想留着以后翻」的情况。

## 常见问题

**切人格后「失忆」了？**

隔离模式下每个人格是独立对话，第一次切过去当然是空的。想带上之前的记录，打开 **开关隔离时带上已有聊天记录**；想永久共享，关掉 **每个人格独立记忆**。

**换默认人格后，新人格会看到旧人格说过的话？**

会，这是 **接管旧有对话**（`claim_legacy_conversation`，默认开）带来的副作用。

会话里如果已经存在一条没有铭牌的对话——既没绑人格、也没有标题，通常是装插件之前就在用的那条——插件会让**当前默认人格**接管它，这样旧记录不会丢。但正因为「谁是默认人格谁接管」，你在 WebUI 里换一次默认人格，新默认人格接管的还是同一条对话，于是它会读到上一个人格说过的话。两个人格风格差异大时，表现就可能跑偏。

想彻底隔开：把这个开关关掉。换默认人格之后各自拿各自的对话，互不可见；代价是原来那条对话的历史不再被任何人格继承。

**用关键词切换人格不受影响**。关键词命中的都是非默认人格，它们各自有独立对话，看不到默认人格的聊天记录。

**从非隔离模式切回隔离，会带上共享对话的历史吗？**

会。非隔离模式下所有消息都写进同一条 `[共享]` 对话。切回隔离后，新人格第一次建对话时会把这条共享对话的历史复制过去，免得切模式丢上下文。

不想带的话，切回隔离后先 `/reset`；或者把那条 `[共享]` 对话删掉，让它没有可继承的来源。

**关键词命中了还会调 AI 判断吗？**

不会。关键词优先级最高，命中直接切，零延迟零消耗。

**AI 判断会拖慢回复吗？**

通常一两秒。和主回复是串行的，会有这点延迟。想彻底去掉就关掉 AI 判断。

**判断会误伤吗？**

复用条数设 `2` 时，最坏会误伤 1 条。设 `1` 每条都判断，最准但每条多一次延迟。

**关掉插件后人格还切得回来吗？**

会。插件退出管辖（WebUI 停用、重载、改白名单）时自动把指针拨回主对话、解绑人格绑定，会话回到全局人格。进程被强杀这种极端情况，下次启动也会自动对账。

**人格卡改名了，聊天记录还在吗？**

**人格的名字就是它记忆的钥匙。**插件是按名字认人的，不是按 AstrBot 内部的 UUID。

好消息是 AstrBot 本身不提供改名的入口——WebUI 里只能改人格内容，改不了名字（`update_persona` 接口根本没有 name 参数），所以正常用碰不到这个问题。

要注意的是这几种情况：

- **删掉人格卡，再建一张同名的**：记忆会接上，因为名字一样
- **直接改数据库把名字换了**：旧对话还在，但插件认不出它属于谁了，这个「新人格」会从一条空对话开始，看起来像失忆
- **删掉人格卡且不再重建**：对话留在库里，只是不会再被用到

所以：**想给人格改名，就得接受它的记忆从零开始**。真要把旧记录迁过去，得同时改 `conversations` 表里的 `persona_id` 和 `title`（`title` 形如 `[人格名]`），属于手工操作。

**`/reset` 会清什么？**

默认清掉这个会话下**所有**人格的聊天记录，同时清插件的激活状态和判断缓存。

**装好之后什么反应都没有？**

插件出厂不带人格。如果没在 WebUI 里建人格、也没在配置里选「默认人格」，它会安静地什么都不做，也不会报错。

先去 AstrBot 的人格管理里建至少一张人格卡，再回来把「默认人格」选上。

**改了规则，怎么没立刻生效？**

「判断结果复用条数」默认是 3，改完规则后最多还要等 2 条消息才会重新判断。想立刻生效，发一条 `/dp refresh`，或者把这个值改成 1。

**AstrBot 版本低于 4.25.6 会怎样？**

装不上，或者装上后加载失败。AstrBot 会读 `metadata.yaml` 里的 `astrbot_version` 并**强制校验**，不满足直接抛错拦掉。

下限定在 `4.25.6` 是因为插件依赖的 `get_persona_v3_by_id`（4.21.0 起才有）和 `/reset` 全清要用的 `_clean_group_context_session`（4.25.6 起才有）。再往下的版本核心功能还能跑，但 `/reset` 会退化成只清当前人格那一条。

**支持别的平台吗？**

插件本身和平台无关，理论上都能用。

- **已验证**：QQ 个人号（aiocqhttp，配合 NapCat / SnowLuma）
- **未实机验证**：QQ 官方机器人、Telegram、Discord 等

官方机器人的消息格式理论上一致，但我这边没有环境实测。如果你在别的平台跑通了或者遇到问题，欢迎按下面的方式反馈。

## 工作原理

<details>
<summary>点开看（不感兴趣可以跳过）</summary>

插件挂两个钩子：

```
用户发消息
  ↓
[判断用谁]
  关键词命中？      → 直接切，不调模型
  上次激活没到期？  → 继续用
  缓存还有效？      → 复用上次判断
  都没有            → 调小模型判断（超时 8 秒兜底默认人格）
  ↓
[切换]
  隔离模式   → 切到这个人格对应的对话
  非隔离模式 → 记下决策，稍后叠加人格
  ↓
[回复]
  隔离模式   → AstrBot 按对话的 persona_id 原生注入人格
  非隔离模式 → 插件在 on_llm_request 里把人格叠加/替换进系统提示词
  ↓
[记录]
  把这一问一答写进时间线（内存 + 定期落盘），供下次判断参考
```

**为什么人格走原生注入**

AstrBot 原生注入是在系统提示词后面追加一段 `# Persona Instructions`，Skills 说明、工具约定在它后面继续追加，互不覆盖。插件只需要保证「当前对话绑定的 persona_id 是对的」。

**判断上下文为什么用内存时间线**

隔离模式下历史分叉在不同对话里。刚切完人格那几条，判断模型看不到上一条，容易误判。所以插件自己维护一份跨人格的近期消息，只给判断模型看，不影响实际回复。

**时间线会落盘**

时间线保存在 `data/plugin_data/astrbot_plugin_persona_router/timeline.json`，改动后 3 秒内写入磁盘，重启自动读回。最多保留 256 个会话，7 天没动静的自动清掉，长期运行不会把内存或磁盘撑大。

**人格和历史靠两个锚点**

- `persona_id`（对话上的活绑定）：决定这条对话用谁说话，插件退出时解绑
- `title = "[人格名]"`（永久铭牌）：记录这条对话属于谁，永不抹除

重新接管时靠这两个锚点找回历史，所以关了再开不会串。

</details>

- 修复：非隔离与隔离模式互切、搬迁聊天记录时会把 JSON 字符串二次编码进数据库。插件自己会把这段历史当成空的（切过去就失忆），AstrBot 主流程读到它时会直接抛错
- 修复：非隔离模式下 `/new` 不生效，下一条消息会切回原来的 `[共享]` 对话
- 修复：隔离模式下 `/new` 产生的空对话会成为孤儿，本次新建的人格对话接不上，插件退场时还可能把会话指针拨到空对话上
- 文档：新增「清空历史：`/reset` 和 `/new` 怎么选」，写清两个命令的区别、各自后果，以及 `/new` 之后切不回旧对话这件事
- 文档：常见问题补充「换默认人格后新人格会看到旧人格说过的话」「从非隔离模式切回隔离会带上共享对话历史」，说明 `接管旧有对话` 的副作用与关闭方式
